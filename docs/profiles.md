# โปรไฟล์ของฉัน

ทุกบัญชีที่เปิดใช้งาน เข้าเมนูมุมขวาบน → **โปรไฟล์ของฉัน** (`/profile`) จะเห็นการ์ดสรุปข้อมูลแบบเดิม กด **แก้ไขข้อมูล / รูปโปรไฟล์** เพื่อเปิดฟอร์ม บันทึกสำเร็จจะกลับมาหน้าสรุป กด **ยกเลิก** เพื่อละทิ้งสิ่งที่ยังไม่บันทึก `/account` เดิมยังเปิดหน้าเดียวกันเพื่อรองรับลิงก์เก่า

| บทบาท | ข้อมูลที่แก้ไขได้ |
| --- | --- |
| ทุกบทบาท | รูปโปรไฟล์ เบอร์โทร ที่อยู่ติดต่อ คณะ / สำนักวิชา / หน่วยงาน |
| Student | สาขาวิชา ระดับการศึกษา ชั้นปี เกรดเฉลี่ย สถานะบิดามารดา |
| Officer / Committee / Admin | ตำแหน่งงาน |
| Committee | ความเชี่ยวชาญ |

ข้อมูลในโปรไฟล์ไม่บังคับกรอก และเว้นว่างเพื่อล้างค่าเดิมได้ สถานะบิดามารดาใช้รายการมาตรฐาน และเลือก “อื่น ๆ” เพื่อระบุข้อความเอง ข้อมูลการศึกษาที่นักศึกษากรอกเองยังไม่ใช่ข้อมูลที่ผ่านการตรวจสอบคุณสมบัติทุน ชื่อ รหัสประจำตัว บทบาท และสถานะบัญชียังจัดการโดย Admin การเปลี่ยนรหัสผ่านไม่อยู่ในฟอร์มนี้

## เปลี่ยนอีเมลเข้าสู่ระบบ

ทุกบทบาทใช้ส่วน **อีเมลเข้าสู่ระบบ → เปลี่ยนอีเมล** กรอกอีเมลใหม่ที่เข้าถึงได้และรหัสผ่านปัจจุบัน ระบบยืนยันตัวตนกับบัญชีเดิมก่อนเรียก `auth.updateUser({email})` ไม่เขียนทับ email ในตารางโปรไฟล์เอง และไม่รับ user ID จากฟอร์ม

คง Secure email change ไว้ ให้ยืนยันจากอีเมลเดิมและอีเมลใหม่ เปิดลิงก์ในเบราว์เซอร์ที่ส่งคำขอเพื่อใช้ PKCE callback `/auth/callback` ที่ตั้งไว้แล้ว ระบบกลับหน้าหลักตามบทบาท จากนั้นเปิดโปรไฟล์เพื่อตรวจอีเมลได้ ตรวจ `new_email` จาก Auth เพื่อแสดงสถานะรอยืนยัน เมื่อยืนยันสำเร็จ trigger `portal_sync_email` เดิมจะอัปเดตโปรไฟล์ เพิ่ม version และบันทึกประวัติ

ตรวจวันที่ 22 ก.ย. 2026: Supabase ยังใช้ default SMTP จึงยังไม่พร้อมส่งลิงก์เปลี่ยนอีเมลไปยังผู้ใช้ทั่วไป ต้องตั้งค่า Custom SMTP ใน **Authentication → Emails → SMTP Settings** พร้อมผู้ส่งที่ยืนยันโดเมนแล้ว ตรวจแล้ว Redirect URLs มี `http://localhost:3000/auth/callback` ที่ใช้กับคำขอเปลี่ยนอีเมลนี้อยู่แล้ว (เพิ่ม production URL จริงเมื่อ deploy) การสมัครนักศึกษาจาก `/register` ไม่ใช้ลิงก์ยืนยันอีเมล ส่วนอีเมลแจ้งเตือน workflow ตั้งค่าแยกตาม [notifications.md](notifications.md)

ทดสอบแล้ว: build/lint, เปิดฟอร์มและยกเลิก, ปฏิเสธอีเมลซ้ำโดยไม่ส่งคำขอเปลี่ยนจริง ยังไม่ได้ทดสอบรับลิงก์และเปลี่ยนอีเมลจริง เพราะ SMTP ยังไม่พร้อมและไม่มีอีเมลใหม่สำหรับทดสอบที่ผู้ใช้ระบุ ห้ามใช้บัญชีของสมาชิกจริงเป็นการทดสอบเปลี่ยน credentials โดยพลการ

อ้างอิง: [Supabase updateUser](https://supabase.com/docs/reference/javascript/auth-updateuser), [ข้อจำกัด default SMTP และการตั้งค่า](https://supabase.com/docs/guides/auth/auth-smtp)

หน้านักศึกษาเดิมเป็นตัวอย่างที่บันทึกเฉพาะ state และหายเมื่อรีเฟรช หน้านี้แทนที่ด้วยข้อมูลจริงจาก Supabase ส่วนข้อมูลฐานะครอบครัว บัญชีธนาคาร และเอกสารประกอบการสมัครยังต้องพัฒนาในโมดูลใบสมัคร/เอกสาร ไม่มีการอ้างว่าข้อมูลหรือเอกสารครบ 80% อีกต่อไป

## ฐานข้อมูลและสิทธิ์

- ใช้ `portal_profiles` พร้อม `update_my_profile` RPC ตรวจ `auth.uid()` และ `active` ในฐานข้อมูล ไม่รับ ID เป้าหมายจากผู้ใช้
- ทุกบทบาทแก้ได้เฉพาะตัวเอง แม้ Admin ก็ต้องใช้หน้าจัดการสมาชิกแยกเมื่อต้องการจัดการผู้อื่น
- ไม่เปิด direct UPDATE ให้ client เพื่อให้ทุกการแก้ไขผ่านการตรวจข้อมูลและ audit
- `version` ป้องกันบันทึกทับข้อมูลใหม่ หาก Admin หรือแท็บอื่นแก้ระหว่างกรอก ให้รีเฟรชแล้วตรวจข้อมูลใหม่
- ข้อมูลเฉพาะบทบาทตรวจซ้ำในฐานข้อมูล ไม่ใช้การซ่อนฟอร์มเป็นการตรวจสิทธิ์
- ประวัติเก็บใน `portal_audit_log` และ Admin ดูได้ที่ `/admin/audit`
- รูปอยู่ใน private bucket `portal-avatars` เจ้าของที่เปิดใช้งานเท่านั้นเข้าถึงได้ รูปปัจจุบันอ่านผ่าน `/account/avatar` โดยไม่รับ user ID หรือ file path จาก URL
- รับ JPG/PNG/WebP ไม่เกิน 2 MB และ 20 ล้านพิกเซล ตรวจจากไฟล์จริง แปลงเป็น WebP 512×512 และลบ EXIF ก่อนจัดเก็บ ไม่รองรับภาพเคลื่อนไหวหรือ SVG
- ใช้ path ใหม่ทุกครั้ง ไม่เขียนทับรูปเก่า บันทึก profile สำเร็จแล้วจึงลบรูปเก่า หากลบ Storage ไม่สำเร็จอาจมีไฟล์ที่ไม่ได้ใช้งานเหลืออยู่ รูปที่ใช้งานไม่ถูกลบก่อนบันทึก

## เตรียมเครื่องทีม

รัน `npm ci` หลังดึงโค้ด เพราะเพิ่ม dependency `sharp` ให้ใช้ Supabase project เดียวกันและตั้งค่า `.env.local` ของแต่ละเครื่องตาม `.env.example` ห้าม commit คีย์ลับหรือไฟล์ `.env.local`

โปรเจกต์ร่วม `project331ระบบติดตามทุน` ใช้ migrations ต่อไปนี้แล้ว จึงไม่ต้องรันซ้ำใน SQL Editor:

- `20260913192030_staff_committee_self_profile.sql`
- `20260913193820_all_roles_self_profile.sql`

สำหรับฐานข้อมูลใหม่ ให้ใช้ migration history ทั้งชุดตามลำดับ รวม Auth/Admin migrations ก่อนหน้า

## ตรวจสอบ

```bash
npm run lint
npm run build
node --test scripts/check-avatar.mjs
```

`supabase/tests/self_profile_permissions.sql` ใช้บัญชีสังเคราะห์ใน transaction และ rollback ทั้งหมด ทดสอบทั้ง 4 บทบาท การห้ามแก้ข้อมูลคนอื่น การป้องกันสิทธิ์ การตรวจข้อมูล version audit และ storage ownership

`scripts/check-profile-storage.mjs` รับ JSON ของบัญชีทดสอบ `{email,password,role}` ทาง stdin และรันด้วย `node --env-file=.env.local` โดยไม่พิมพ์ข้อมูลเข้าสู่ระบบ ทดสอบหน้า `/profile` และอัปโหลด/อ่าน/ลบเฉพาะรูปทดสอบใหม่ของตนเอง ไม่แก้รูปปัจจุบัน ต้องมีเว็บรันที่ localhost:3000 หรือกำหนด `AUTH_TEST_BASE_URL`

ตรวจหน้าเว็บ: เข้าระบบแต่ละบทบาท → โปรไฟล์ของฉัน → แก้ข้อมูล → บันทึก → รีเฟรช → ตรวจว่าอยู่ครบ และตรวจรูปในเมนูมุมขวาบนด้วย

Supabase Advisor ยังมีคำเตือนเดิมเรื่อง [Leaked Password Protection](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection) ซึ่งแยกจากสิทธิ์โปรไฟล์นี้
